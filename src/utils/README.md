# Pre-Computed Data & Embeddings (`src/utils`)

> [!WARNING]
> **DEMO & TEST DATA NOTICE:**
> All files in this directory (`tools-registry.json`, `faq-embeddings.json`, `query-cache.json`) contain mock seed data for demonstration, local development, and automated testing.
> **Before deploying to a production environment:**
> 1. Delete or clear `query-cache.json` (or set a production database/Redis path).
> 2. Replace `faq-embeddings.json` with your real corporate FAQ data.
> 3. Overwrite `tools-registry.json` with your verified enterprise production tool schemas.

---

## 1. `tools-registry.json`
* **Purpose:** Stores registered agent tools alongside their pre-computed, 384-dimensional vector embeddings generated by the local SML (Semantic Model Layer) using `all-MiniLM-L6-v2`.
* **Why it exists:** When the RAG engine starts, computing embeddings for every registered tool on each cold start adds unnecessary startup latency. This registry acts as an offline cache. If a tool's description hasn't changed, its embedding is reused directly without model inference.
* **Schema:**
  ```json
  {
    "_description": "Pre-computed tool embeddings registry for SML...",
    "version": "1.0.0",
    "tools": [
      {
        "name": "check_live_stock",
        "description": "Retrieves current warehouse stock count and price...",
        "embedding": [0.05032, -0.02154, ...]
      }
    ]
  }
  ```
* **Included Sample Tools:**
  1. `check_live_stock`: Real-time stock querying.
  2. `track_order_status`: Live shipment and courier tracking.
  3. `cancel_order`: Order cancellation and refund initialization.
  4. `calculate_shipping_cost`: Shipping and logistics calculation.

## 2. `faq-embeddings.json`
* **Purpose:** Stores pre-embedded FAQ (Frequently Asked Questions) items with question, answer, category, and 384-dimensional embedding vectors.
* **Why it exists:** Enables instant, zero-cost semantic search for common customer queries. Incoming user questions can be matched via cosine similarity / dot-product directly against this dataset. If similarity exceeds a threshold (e.g. 0.82), the engine answers directly without triggering external LLM API calls.
* **Schema:**
  ```json
  {
    "_description": "Pre-computed FAQ embeddings for semantic question answering...",
    "version": "1.0.0",
    "faqs": [
      {
        "id": "faq_return_policy",
        "question": "What is your return policy...",
        "answer": "You can return any undamaged item within 14 days...",
        "category": "returns",
        "embedding": [-0.01471, 0.06034, ...]
      }
    ]
  }
  ```
* **Included Sample FAQs:**
  1. `faq_return_policy`: 14-day return and refund policy.
  2. `faq_shipping_times`: Delivery times and courier options.
  3. `faq_payment_methods`: Credit cards, bank transfers, and installment options.
  4. `faq_order_tracking`: How to track packages with order IDs.
  5. `faq_customer_support`: Live support hours and contact email.

## 3. `query-cache.json`
* **Purpose:** Serves as the seed file / persistent snapshot for `CacheManager`.
* **Why it exists:** Re-answering identical queries wastes tokens and increases latency. When a query is answered by the RAG Engine, frequent hits are persisted to this JSON file. On startup, `CacheManager` hydrates its in-memory LRU cache from this file.
* **Schema:**
  ```json
  {
    "iade politikasi nedir?": {
      "answer": "Yasal iade suremiz teslimat tarihinden itibaren 14 gundur...",
      "intent": "FAQ",
      "resolvedBy": "CACHE",
      "appliedRules": ["Iade suresi tum urunler icin 14 gundur."],
      "latencyMs": 3
    }
  }
  ```
